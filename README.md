# Meterbook 数据用量结算

对双边数据使用记录进行核对、费率计算、争议处理、调整结算和成本分配。金额使用十进制字符串，时间使用明确的 UTC 偏移；完整性摘要不提供外部身份认证。

## 封账期间差异分析

`variance.analyze` 比较同一合同下两个**已封账期间**的费用变化，全程只读冻结的发票与费率快照，不改动任何账单：

- 从发票链取封账金额，并按冻结费率定义逐行**独立复算**，复算不一致直接拒绝，报告同时给出原目标金额和可复算的反事实组合；
- 将费用变化拆为总用量（volume）、计量项结构（mix）、费率（rate）三个因素，对全部 3!=6 种切换顺序求 **Shapley 对称均值**，交互项由各因素对称分摊，不会全部塞给最后一个因素；
- 反事实网格覆盖 2³=8 个因素联盟，使用精确分数运算，仅在落盘到最小币种单位时用最大余数法取整，分项贡献逐分精确守恒；
- 新增或停用的计量项、以及一侧用量为零的不可比口径，单独列入结构对齐并保留全部金额，绝不构造零价格；可通过 `meter_align` 显式声明计量项重命名映射；
- 贷项通知单与追溯调整依据发票链单独归因，不计入当期消费分解，贷项核销与退款作为独立信息列示，既不混入消费也不遗漏；
- 遵守冻结费率中的阶梯、包含量、最低/最高收费以及合同币种与舍入规则；
- 交换两个比较期间时，每个因素的贡献方向恰好相反。

`variance_desk.freeze` 把分析结果按标识与递增版本号不可变地落库（带摘要校验）；后续修订重新冻结即生成新版本，历史版本保持只读。

## 运行环境

使用 Python 3.11，核心功能依赖标准库和 SQLite。演示和测试只使用本地合成数据，不需要账户、设备或外部运行服务。请从项目根目录执行命令。

## 检查与运行

构建检查验证语法，测试使用临时数据目录，不会连接远端服务。

```sh
python3 -m compileall -q meterbook
python3 -m unittest discover -s tests -v
python3 -m meterbook replay fixtures/settlement.json
```

演示会展示产品的实际数据处理和输出，运行结束自行退出。查看现有接口：

```sh
python3 -m meterbook capabilities
```

## 目录与数据

meterbook/ 保存领域逻辑和请求入口，tests/ 包含正常行为、边界与恢复测试。例子中的标识和记录为合成资料，不包含真实人员或生产测量。业务目录和本地数据库由调用者指定，应与源码分开保存。

## 干净环境复现

容器定义固定运行时版本。构建时准备环境，运行时无需网络；每次启动会复制只读源码到临时工作目录，测试产生的文件不会写回仓库。

```sh
docker build -t local-product-check .
docker run --rm --network none local-product-check
```
